# TODO: Lada 21129 (1.6 16V, CR 10.5, port injection) on rusEFI m74_9

Created 2026-08-17. Working list for the 21129 tune on m74_9 (AT32F435 + L9779).

## Table analysis conclusions (VE / ignition / lambda), 2026-08-17

Data source: stock M74 modeled maps, IM=0 (long runner) and IM=1 (short runner).

- Primary VE (veTable, long runner): matches the stock model within +/-1% up to
  4700 rpm. No changes needed.
- Second VE (secondVeTable, short runner): the 7000 rpm column holds the model's
  6250 rpm value, so interpolation overshoots VE by 2-3% in the 6000-6250 zone
  (mixture leaner than target at the top). NEW values for the 7000 rpm column
  (rows = load, kPa):
    load 85:  81.9 -> 78.0
    load 90:  82.3 -> 78.3
    load 95:  83.1 -> 79.4
    load 100: 82.7 -> 79.0
  Remaining rows (optional, loads 20..80): 61.4 / 64.9 / 68.3 / 70.8 / 71.7 /
  73.0 / 74.4 / 75.5 / 76.2 / 76.9 / 77.2 / 77.4
- Ignition: both maps (ЧН / ПМ) reproduce the stock calibration within
  +/-1.5 deg, in the safe direction. No changes needed.
- Lambda: 0.84-0.82 is the correct power line for RON95 with no knock control.
  Do NOT lean out (no knock sensor means mixture is the only knock margin).
  Minor: level the top-right corner 0.816/0.823 -> 0.82 for consistency.
- Injectors: 215 cc/min gives ~64% duty at the 6250 cut - OK. Verify actual vs
  target lambda on a wideband: if 215 cc/min is the 3 bar rating and the rail
  is the stock 3.8 bar, the mixture runs ~12% rich systematically.
- fuelReferencePressure = 51 is nonsense in kPa, but without a fuel pressure
  sensor the compensation is inactive and the value has no effect.
- cylinderBore in the tune is 87.5; the 21129 is 82 mm (affects the auto knock
  frequency - we set knockFrequency explicitly instead).
- Torque section: NOT used by the engine control (rusEFI has no torque model).
  torqueTable only feeds Lua getTorque(). Nothing to fill.

## Intake geometry flap + second tables

- Fill crossover IM=0/IM=1 is ~4700-4900 rpm at all loads. Recommended switch:
  ON ~4900-5000 rpm, OFF ~4700 rpm (hysteresis).
- Currently the flap is NOT driven (all gppwm channels on NONE) and the blend
  is not configured (secondVeBlendParameter), so the second tables are never
  used: above 5000 rpm the engine runs the long-runner map (VE 77-82% instead
  of 83-90%) - the top end is strangled.
- Plan: gppwm channel on pin "Intake manifold geometry control valve" (AA2,
  gp_low), duty table 0% below 4800 / 100% above 5000 rpm;
  secondVeBlendParameter and secondIgnitionBlendParameter = that channel;
  blend bins [0, 100] -> values [0, 100].
  Check the solenoid polarity on the car: with vacuum applied the flaps close
  (long runner, low rpm), so the low-rpm table must be the primary one.
- Save Tune writes only page 0: the <page number="3"> block is lost, so always
  load the tune from the file patched by m74_9_clb_to_msq.py (it re-adds the
  second-table page).

## Knock (PRIORITY - in progress)

- Board inputs exist: AA3 = "Knock sensor +", AB3 = "Knock sensor ground"
  (connectors/m74_9.yaml).
- The MCU pin the conditioner feeds is NOT documented in the yaml. Assumed
  PF7 = ADC3 IN5 (hellen_knock_config.h precedent). VERIFY on the bench:
  - adc_report: the knock channel idles at ~1.65 V (open inputs read ~3.28 V);
  - tap the knock sensor / wiggle AA3: exactly one channel shows a spike.
  If another channel reacts - one line in knock_config.h.
- Conflict resolved: EFI_ADC3_SLOW (CLT/IAT on F-port pins) now shares ADC3
  with EFI_SOFTWARE_KNOCK. Slow read skips while a knock window runs
  (max ~40 us every 50 ms), knock windows skip while the slow read runs
  (rare). Done in stm32_adc_v2.cpp + software_knock.cpp.
- 21129 knock: 82 mm bore -> ~7.0 kHz (resonant sensors), knockFrequency = 7000,
  double frequency = OFF. Window 20..65 deg ATDC is only a starting point;
  calibrate knockBaseNoise/gains afterwards.
- Until knock is calibrated there is no detonation protection: on RON95 keep
  margin, if pinging is heard pull 1-2 deg in the WOT rows at 2900-4700 rpm
  of both ignition maps.
